# Changelog

## Unreleased

- An update whose record has a key named like a key parameter (`__pkey__0`) raises
  instead of overwriting the key binding, as Python Asqueel 0.9.0 does (asqueel#24).
  A delete binds its key from the key columns only.
- Parity reference raised to Python Asqueel 0.9.0 at commit `baf4582`; the fixtures
  regenerated by the 0.9.0 oracles are unchanged. The oracles open a `SessionDb`
  with `db.session()` (asqueel#56).
- `python/asqueel_transfer.py` requires Python Asqueel >= 0.9.0: `load_transfer` writes
  through `AsqueelDb(...).session()`.

## 0.2.0 — 2026-10-25

Parity with Python Asqueel 0.7.0 at commit `84408eb` (main after 0.7.0, with the recipe
source saved in TYTX), asqueel-migration 0.3.5, genro-builders 0.30.0, genro-bag 0.28.0,
genro-tytx 0.16.4.

### Model

- Grammar regenerated from Python. Options take the legacy names `sysFields`, `counter`,
  `relidx`, `df`, `fullUpd`, `sysrecords`; the column flag is `readOnly`.
  `relation(related_column, ..., insensitive=)` replaces `to` and `case_insensitive`.
- `schemas`/`schema`, `weak_relation`, `validation`, `encryption` and the options
  `record_hash`, `audit`, `protection`, `attachments` leave the grammar. A model starts
  from `packages().package(...)`; a composite primary key names its `compositeColumn`.
- No `x_*` attribute in the source or the resolved model. A relation without a foreign
  key indexes its columns; hierarchy fields and copied columns come from the
  `hierarchical` option.
- The grammar checks `retention.days >= 0`, `hierarchical.depth >= 1`, driver timeouts
  `>= 0` and `package.sqlprefix`; `column` declares the six `sql_pg_*`/`sql_sqlite_*`
  parameters.
- `SqlSourceBag` is registered as a TYTX subtype under the Python name.
  `recipe.toTytx()` and `SqlBuilder.fromTytx()` save and reload the recipe source; a
  file written by Python loads in JavaScript and the other way round.
- Removed `toJSON()`, `DbModel.fromJSON()`, `modelToJSON` and `modelFromJSON`: the
  resolved model has no JSON form, as in Python.
- Building the model checks the main connection settings, as Python `AsqueelDb` does.

### Migrations

- The migration JSON is rendered from the prepared source, as the Python
  `SqlMigrationRenderer` does. The internal physical builder is removed.

### Queries

- `#PERIOD` decodes natural-language dates with `parseDateExpression` of
  `@genrojs/toolbox` (>=0.19.0), as Python does with `genro_toolbox.dates`. The runtime
  option `parseDateExpression` is removed and raises an error.
- `formulaColumn_<x>()` columns are built at the first read of the table virtual
  columns, also when a write is compiled.
- `#TEMPLATE` and `#IN_RANGE`, with NULL-safe concatenation, Unicode names and inclusive
  or open bounds.
- Synchronous compiler callbacks (`sql_formula_*`, `subquery_*`, `env_*`,
  `formulaColumn_*`) in the `methods` runtime registry, with an environment cache.
- Scalar and `EXISTS` subqueries, `select_*`/`exists_*` in formulas, `subQueryColumn`
  and `aggr()` over inverse relations and virtualRelation (count, sum, avg, min, max,
  ordered join, to_json).
- Read compiler: nested formulas with local `var_*`/`var_kwargs` parameters, `#THIS`,
  `#ENV` from a snapshot, composite columns, also as automatic primary key.
- String literals, identifiers and SQL comments no longer produce parameters.

### Write cycle

- `table.insert/update/delete` run the Python write cycle: system fields, legacy22
  keys, timestamps and users, defaults, protected fields and asynchronous JavaScript
  hooks, with atomic rollback also of nested writes.
- Hierarchies (paths, moves, reordering, inheritance, linked roots, deletion and
  archiving of descendants), `counter` and `relidx`.
- Application `onUpdate` cascades on physical relations (`cascade`, `raise`, `ignore`).
- Integer binding is consistent across Node.js, Bun and the browser.

### Files and offline

- CSV, JSON and TYTX imports through `table.sql_insert`: incremental reading, blocks of
  1,000 records, adaptation from the model, automatic keys, no triggers, atomic transactions.
- Python → browser → Python transfers: the recipe source in TYTX, complete or selected by
  package or table, TYTX record snapshots including Bag (X) and blob (O) fields, atomic
  loading with explicit NULLs and export from the local database.
- Offline playground: versioned asset cache, persistent workspace, CRUD on the loaded
  model and recovery after a browser restart without network.
- A single Gramlot HTML file opened with `file://`, with the worker and SQLite WASM
  embedded; `openBrowserSQLite(name, {wasmBinary})` fetches no WASM.
- The offline meeting demo: 86 actions compared with Python, workspace upgrades,
  minutes and attachments.

### Documentation

- English manual built with Sphinx for Read the Docs; shared concepts link to the
  Python documentation.

### Breaking changes from 0.1.x

- Option and attribute names follow the Python grammar (see above).
- `insert`/`update` return the record completed with SQL defaults; the explicit
  `returning` option is withdrawn. Missing parameters become NULL; `limit: 0` adds no LIMIT.

## 0.1.1 — 2026-10-21

- Removed the upper bounds of the Genro and Gramlot tools; every CI suite updates the
  internal tools to the latest releases.
- Automatic npm publication from GitHub tags through Trusted Publishing (OIDC), with a
  check of the installed tarball and of the package downloaded from the registry.
- The release reuses the CI of the integrated commit. No runtime API change.

## 0.1.0 — 2026-10-21

- First public npm release of `@asqueel/asqueel-js`, with ES module entry points for the
  model, SQLite migrations and the Node.js, Bun and browser adapters.
- Hierarchical models and migrations compared with the pinned Python reference,
  including the precedence of `indexed=False` on system fields.
- Experimental: full query parity, Python application behaviors, a reusable worker API
  and offline loading are outside this release.
